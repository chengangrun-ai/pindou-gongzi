## 3. 处理流水线（8 步，顺序不能变）

```
原图
 ↓ ①去水印
 ↓ ②硬裁（可选）
 ↓ ③抠图去背景
 ↓ ④裁到主体 + 补正方形
 ↓ ⑤按图定分辨率（逐档试，取还原度最高的）
 ↓ ⑥拼豆取色
 ↓ ⑦渲染四张图
 ↓ ⑧出带标/无标两套 + 更新台账
```

### ① 去水印 / 去署名

**这一步最容易翻车，必须逐张检查。**

两种方法：
- `clone_fill(im, rect)`：把矩形上方的同宽区域复制下来盖住 → 适合纯色/渐变背景上的签名
- `median_fill(im, rect)`：用四周一圈的中位色填掉 → 适合纯色块上的文字

**如果两种都不干净，直接裁掉**（`HARD` 硬裁字典）。

⚠️ **坑**：`square_crop` 会向外扩张，只改 bbox 是切不掉边角水印的。
必须先 `im.crop(HARD[fn])` 再方形化。

**必须逐张看的部位**：底部 20%、右下角、左下角。
已知有问题的：`修炼索隆`（hoshiai art）、`半边山治`（Komi logo + 喇叭图标）、
`霸总Kitty`（搜索图标）、`草莓Kitty`（"@请勿商用"文字）、`耍帅路飞`（签名）、`Q版山治`（SANJI）。

### ② 硬裁（可选）

有些图下方有角色名或水印，先切掉再处理。存在 `batch34.HARD` 字典里。

### ③ 抠图去背景 ★关键

**这是整个流程的灵魂。** 不做这一步，出来就是一整块黄底，很丑。

```python
def cutout(im, tol=11, big=45):
    A = np.asarray(im.convert("RGB")).astype(np.float32)
    # 判据一：与四边中位色接近（纯色底）
    edge = np.concatenate([A[0,:], A[-1,:], A[:,0], A[:,-1]])
    gcol = np.median(edge, 0)
    d1 = np.abs(A - gcol).max(2)
    # 判据二：与大半径模糊接近（渐变底）
    bg = np.stack([gaussian_filter(A[...,c], big) for c in range(3)], -1)
    d2 = np.abs(A - bg).max(2)
    near = (d1 < tol*2) | (d2 < tol*0.7)
    # ★ 连通性约束：只有和四边连通的才算背景
    lab, _ = ndimage.label(near)
    ids = {lab[0,:], lab[-1,:], lab[:,0], lab[:,-1]} - {0}
    bgmask = np.isin(lab, list(ids))
    # 填回主体内部的小洞
    ...
    alpha = np.where(bgmask, 0, 255)
    # 羽化 + 收紧阈值去白边
```

**为什么必须两个判据 + 连通性：**

| 只用一个判据 | 结果 |
|---|---|
| 只用 d1（边角同色） | 渐变绿底（修炼索隆）完全抠不掉 |
| 只用 d2（局部模糊） | 角色周围留一圈黄边 |
| 不用连通性 | 角色内部同色区域（比如黑西装）被误删 |

连通性是最后一道保险：角色内部就算和背景同色，因为被黑色轮廓挡住、连不到画面边缘，也不会被抠掉。

### ④ 裁到主体 + 补正方形

```python
trim(im, pad=0.04)      # 按 alpha 裁到主体外框

```

### ⑤ 按图定分辨率

**每张图分辨率不同**，不搞统一规格。

```python
LADDER = (128, 160, 192, 224, 256)   # 候选格数
Kof = lambda c: int(min(64, 20 + c/5))  # 色数随分辨率走，上限 64

for c in LADDER:
    small = cut.resize((c*3, c*3), LANCZOS)   # 缩到 cols*3，保证 n=3、输出正方
    white = on_white(small)
    grid, pal = beadify_fast(white, c, K=Kof(c))
    grid = np.where(grid_alpha(small, c) > 0.35, grid, -1)  # 角色外置空
    score = fidelity_score(white, grid, pal)
    取分数最高的一档
```

### ⑥ 拼豆取色（`fastgrid.beadify_fast`）

```python
1. 轻度鲜艳度补偿：A += (A-mean) * 0.20 * clip(|A-mean|/0.14, 0, 1)
2. 自适应色板：5bit 颜色直方图 + 加权 k-means（weight_pow=0.45）
   → 小面积但独特的颜色才有发言权，不然大片单色会吃光色板名额
3. 色板去重：Lab 距离 < 7 的合并
4. 逐像素量化到最近色板色
5. 整格取众数（向量化：`(blk==k).sum(axis=(1,3))`）
6. 暗色优先：暗色占格子 > 22% 时强制用暗色（保住描边）
```

## 4. 视觉规范（照 pintoo 模仿）

### 4.1 亚麻纸底 ★

**必须能看出织纹。** 之前振幅只有 3.6，肉眼等于纯色，被退回两次。

```python
T = 5.0                                  # 一根纱的宽度
ph_x, ph_y = 每根纱的随机相位             # 避免死板
vx = cos(x * 2π/T + ph_x) * 0.5 + 0.5    # 经线
hy = cos(y * 2π/T + ph_y) * 0.5 + 0.5    # 纬线
weave = (vx*0.55 + hy*0.55) - 0.55 - vx*hy*0.30   # 交叉处压暗 = 平纹
arr = base + weave * 15                  # ★ 振幅必须 15 左右
再叠：短纤维(×7) + 横向长纤维(×6) + 软折(×12) + 左上定向光 + 暗角
底色 #EEECE7（偏暖灰）
```

### 4.2 水印 ★

**小而密**，不要大而稀。

| 参数 | 值 |
|---|---|
| 字号 | 角色宽度的 **1/15** |
| 间距 | tile 尺寸的 **0.92 倍**（几乎相接） |
| 透明度 | 155 |
| 角度 | 28° |
| 文字样式 | 灰字 `#929094` + **白色描边**（浅底深底都看得见） |

## 8. 踩坑清单（血泪教训，别再犯）

### 8.1 还原度

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 68 格就想"还原" | 浅粉肤色判成灰、鼻子被去噪吃掉 | **128 格起步**，复杂图 256 格 |
| 去噪时只保护暗色 | 高饱和小细节（鼻子/蝴蝶结/眼睛）被邻域吃掉 | 同时保护 `chroma > 22` 的色 |
| 还原度算法错位 | 分数随分辨率上升反而下降 | `score()` 必须**在被裁过的同一块源图上**比 |
| 用锐利 MAE 当还原度 | 1px 边缘错位把分数拖到 0.85 | 用 `blur=3` 的模糊版，反映的是"颜色对不对" |
| 带 -1 的 grid 直接评分 | -1 被当成最后一个色号，分数崩到 0.3 | 先 `np.where(g>=0, g, white_idx)` |

### 8.2 构图

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 按主体 bbox 直接裁 | 窄长主体算出 18752 颗，完全失控 | **统一方形裁切** |
| `square_crop` 外扩 | 想切掉的水印又被圈回来 | 先 `im.crop(HARD)` 硬裁再方形化 |
| 自动 bbox 阈值太高 | 黄色背景上的黄头发、白字全漏掉，裁切切在头上 | 阈值 95 对亮底失效，改 `|img - blur(img,45)|` 局部对比 |

### 8.3 视觉

| 坑 | 后果 | 正确做法 |
|---|---|---|
| 亚麻纹理振幅 3.6 | 肉眼等于纯色 | **振幅 15** |
| 白字水印 | 浅底图上完全看不见 | **灰字 + 白描边** |

## 12. 关于"还原度 99.9%"

客户提过 99.9%，**这是数学上不可能的**，别硬扛，直接给数据：

| 格数 | 颗数 | 还原度（平均） |
|---|---|---|
| 96 | 1.0 万 | 94.7% |
| 128 | 1.6 万 | 97.0% |
| 192 | 3.7 万 | 97.8% |
| 256 | 6.6 万 | **98.3%（上限）** |
| 320 | — | 反而下降（格子小于 1px） |

**原因**：一颗豆只能一种颜色，格内所有颜色变化必然被平均掉；
64 色量化本身就有约 1.5% 误差。
要到 99.9% 只能让一颗豆 = 一个像素 = 54 万颗 = 3.6 米，那不是拼豆。

**话术**：把表给客户看，让他选"要数字"还是"要能卖"。

## 13. 真人照片怎么处理（补充）

**平色底判据对照片无效**——房间、街道、渐变天空都抠不掉。
照片必须用 `cv2.grabCut` 做前景分割。

```python
def cutout_photo(im, rect_ratio=(0.20, 0.04, 0.60, 0.94), iters=6):
    """rect_ratio 是「主体大致所在矩形」，相对宽高的比例"""
    arr = cv2.cvtColor(np.asarray(im.convert("RGB")), cv2.COLOR_RGB2BGR)
    h, w = arr.shape[:2]
    rx, ry, rw, rh = rect_ratio
    rect = (int(w*rx), int(h*ry), int(w*rw), int(h*rh))
    mask = np.zeros((h, w), np.uint8)
    bgd = np.zeros((1,65), np.float64); fgd = np.zeros((1,65), np.float64)
    cv2.grabCut(arr, mask, rect, bgd, fgd, iters, cv2.GC_INIT_WITH_RECT)
    m = np.where((mask==2)|(mask==0), 0, 255).astype(np.uint8)
    m = cv2.medianBlur(m, 7)          # 去锯齿
    rgba = cv2.cvtColor(arr, cv2.COLOR_BGR2BGRA); rgba[:,:,3] = m
    return Image.fromarray(cv2.cvtColor(rgba, cv2.COLOR_BGRA2RGBA))
```

**依赖**：`pip install opencv-python-headless`

**要点**：
- `rect` 要框住整个主体（含头发、手臂），但不能太贴边，否则 grabCut 会把边缘当前景
- `iters` 6 次足够；再多会过分割
- 分割完必须 `medianBlur(7)`，不然边缘是锯齿
- 如果主体不在画面中央，调 `rect_ratio`

**照片 vs 插画的选择**：

| 输入类型 | 抠图方法 |
|---|---|
| 平色底 / 渐变底插画 | `cutout()`（两个判据 + 连通性） |

## 15. 角色 vs 场景：两种成品图版式（重要）

**不是所有图都浮空。** 判断标准是"有没有可抠的主体"：

| 类型 | 例子 | 版式 | 函数 |
|---|---|---|---|
| **角色 / 物品**（有明确主体，背景是平色或可分割） | 海贼王角色、Kitty、真人头像 | **浮空**：角色透明贴亚麻纸，投影跟轮廓 | `floatcard.float_card()` |
| **整幅场景**（画面本身就是作品） | 艺术摄影、风景、街拍 | **豆板**：整块豆子有厚度 + 投影，像实物板子放纸上 | `brand.render_card()` |

**为什么场景不能浮空**：整幅图抠不出主体，硬做"浮空"就是一块贴上去的矩形，
比豆板还难看。豆板有厚度和投影，反而像"真的拼好放在桌上"。

**判断口诀**：
- 能一眼说出"主角是谁" → 浮空
- 主角是"整个画面"（一片花海、一条街、一片天） → 豆板

### 水印参数（两种版式统一）

| 参数 | 值 |
|---|---|
| 字号 | 豆图宽度的 **1/15**（最小 28px） |
| 间距 | **0.92** 倍 |
| 透明度 | 155 |
| 样式 | 灰字 `#929094` + 白描边 |

⚠️ 之前 `render_card` 里写的是 `bw//6`（1/6），在豆板版上水印巨大，已统一改成 1/15。

## 18. 抠图失败的兜底（GRAB 名单）

平色判据不是万能的。以下情况会残留背景块：

- 背景和主体**同色系**（比如墨绿头发 + 橄榄绿背景）
- 背景有渐变阴影，`d1` 超出阈值，泛洪进不去

**症状**：成品图里主体背后出现一块**边缘笔直的色块**。

**解法**：把该图加进 `batch34.GRAB` 集合，改走 grabCut。

```python
GRAB = {"完整猫猫.jpg", "猫猫美图.jpg"}
```

目前用 GRAB 的两张：
- `完整猫猫` —— 墨绿头发 + 橄榄绿背景，泛洪只吃到一半，残留矩形块
- `猫猫美图` —— 整幅插画带纸纹边框

**判断方法**：抠完把图贴到亚麻纸上缩略看一眼，背景块边缘是"直"的就有问题，
有机曲线是正常的（那是主体轮廓）。

## 20. 低色号精品模式（重要：产品思路）

### 竞品在做什么

参考账号 `香香Puyo`，一张「花神」图纸：
**82×96 格 / 13 色 / 5537 颗**，卖 5 块，2269 赞。

我们的版本：256×256 / 64 色 / 2 万多颗。**客户反馈"颜色太多，看不清色号"。**

### 结论：能做到"少颜色又好看"，但有前提

低色号好看的核心不是"算法压缩"，而是：

1. **原图本身是平涂 + 粗描边**（chibi、卡通、像素风）
2. **格子要大**（≥20px），色号才看得清
3. **色板要"设计过"**，不是 k-means 硬压

### `lowcolor.beadify_low()` 的做法

```python
cols = 88 ~ 96        # 比高保真版少一半以上
K    = 13 ~ 15        # 色号控制在 8-15 个
1. MedianFilter(5) 去噪 → 大片区域变干净
2. k-means 少量聚类
3. 色板合并：ΔE < 15 的近似色合成一个（关键！不然一片白会分成 W1/W2/W4 三色）
4. 逐格众数
5. 暗色优先：暗色占格 > 38% 才判描边（阈值太低描边会糊成点阵）
6. 众数滤波 3×3 两遍，抹碎点
7. 恢复描边：原图里 > 55% 是暗色的格子强制回到暗色
```

### 什么时候能用 / 不能用

| 图类型 | 低色号效果 | 建议 |
|---|---|---|
| chibi、粗描边卡通（万圣Kitty、幽灵Kitty） | ✅ 极好，8-10 色就很干净 | 用低色号 |
| 有明确轮廓的角色（完整索隆、Q版山治） | ✅ 好，10-14 色 | 用低色号 |
| 细节多 / 软阴影（完整路飞、艺术摄影） | ❌ 会碎成点阵 | 用高保真版 |

**判断方法**：把原图缩到 88 格看一眼——
- 主体轮廓还是连续的 → 低色号能做
- 轮廓断成虚线、细节糊成一团 → 走高保真

### 实测对比（万圣Kitty）

| 版本 | 格数 | 色数 | 豆数 |
|---|---|---|---|
| 高保真 | 224×224 | 55 | 25,015 |
| **精品低色号** | **88×88** | **8** | **3,277** |

豆数降到 **1/8**，但视觉上更干净、色号看得清、客户拼得动。

## 22. 精品低色号版：最终定稿规则

用户要求：**「不碎的前提下，能压少点就压少点，但要尽量还原原图」**

### 量化标准（`premium.py`）

| 指标 | 阈值 | 含义 |
|---|---|---|
| **碎点率** | **≤ 0.048** | 8 邻域里同色 ≤2 个的格子占比。越低越干净 |
| **还原度** | **≥ 0.90** | 色彩 MAE（blur=3） |
| 格数阶梯 | 96 → 112 → 128 → 160 | 从小到大试，先满足就停 |
| 色数阶梯 | 10 → 12 → 14 → 16 → 20 → 24 | 从少到多试，先满足就停 |

**逻辑**：先试最小格数 + 最少色数；碎了就加色，还碎就加格数；全阶梯都不达标 → **不做精品版，保留高保真版**。

### 结果（47 件）

| 项目 | 数值 |
|---|---|
| 有精品版 | **34 件** |
| 色数 | **5 – 17 色，中位 9 色** |
| 豆数 | 2,707 – 12,544 颗 |
| 还原度 | 90.0% – 98.1% |
| 碎点率 | 全部 ≤ 0.048 |
| 没做精品版 | 13 件（细节太多，压不下去） |
